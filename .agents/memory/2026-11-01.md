# 2026-11-01 — consolidated WS spec implemented (op store + coordinator + admin ops)

The consolidated spec from the user's other session was implemented on
`wip/do-websocket-migration` across three commits (921f4d7 server, ecf95fd client):

- **The DO is the sequential op store.** Ops log to DO SQLite (whole op JSON: type,
  target/targetSha, payload, cid, ct — marks carry their target at op level, so the log
  must store the WHOLE op, never just the payload). An in-memory snapshot folds each op;
  D1 is the cold snapshot store, touched at the edges: upload ops no longer write D1 in
  the hot path — `/l/:id36` queries the DO first (internal photo lookup) and falls back
  to D1; migrate export triggers an internal flush (fold log → D1, clear), import
  rehydrates the DO afterwards.
- **Timestamps: server-authoritative ts + client ct preserved.** The DO stamps ts per op;
  the client's commit time rides `ct` and display times take `min(ct, ts)`. This
  reconciles the two conflicting instructions (summary item 3 vs the earlier offline
  message).
- **Catch-up:** hello carries lastSeq; the DO answers incremental ops after it, or a
  whole snapshot when lastSeq is 0/below the retained window. Feedback ops are
  root-only on the wire.
- **Kick-dedup:** a newer connection of the same user closes the older one (4001); the
  kicked client shows the sync button and does not auto-reconnect (user-confirmed).
- **Client:** `sync/coordinator.ts` (SharedWorker core + shell) owns the single
  WebSocket, lastSeq (localStorage), backlog flush, and ack bookkeeping by cid. Tabs
  queue into the shared oplog and apply broadcast ops live (user-confirmed: real-time).
  The engine stamps cid + ct, skips its own echoes, applies foreign ops through
  appStore.applyServerOps (all op types). Admin CRUD queues as ops; optimistic creates
  are replaced when the echo assigns the real id; a dropped op rolls back with
  copy.api refusal text (read dynamically — the copy gate's one dynamic subtree).
- **Not done / rejected:** videoBudget stays deleted (the viewport top-band rule in
  WaterfallLayout supersedes the fixed-3 budget; spec item 17 is the operative one).
  e2e mocks still speak HTTP `/sync` and need a routeWebSocket rework.
- Verification: lint / ts-check / test all green at each commit (199 tests).

## Merge-readiness review pass (evening): four defects, two of them platform-only

A full review of `wip/do-websocket-migration` against `origin/main` (d729eb5) found the
unit suite green (201 tests) while shipping real defects. All four were confirmed by
driving the **actual dev stack**, not just the harness.

- **B1 — a non-root `delete` reached D1.** `applySnapshotOp` returned `false` for an
  unauthorized op, and `ingest()` ignored the result: it stored the op, broadcast it, and
  the next archive ran `DELETE FROM photos`. Fixed by refusing unauthorized (and
  over-length announcement) ops **before the log**, answering `{error:'op_dropped',cid}`
  — the frame the client already knew how to roll back, and which the server had never
  sent. Live-verified: guest `selfId=51` got `op_dropped`, no broadcast, photo still there.
- **B2 — a client ahead of the log starved.** `internal/rehydrate` reset the log to seq 0,
  so a client claiming `lastSeq=2` matched neither the snapshot branch nor the incremental
  one and received an empty frame forever. `fullSnapshot` now also triggers when
  `lastSeq > maxSeq`.
- **B3 — create ids were never stamped.** Clients replace their optimistic temp-id row from
  `payload.id`, which the server never wrote. `stampId()` now writes the allocated id onto
  the op before persist/broadcast.
- **M1 — the overlong-announcement guard vanished with the admin routes.** Restored as a
  pre-log refusal. **N6** — `web/src/sync/` was invisible to the layering guard
  (`layerOf()` returned null); ranked as `core` and proven with a planted inversion.

Two pitfalls the harness could not have caught, both found only by running the stack:

1. **`wrangler.toml` declared `new_classes`** for a DO that uses `state.storage.sql` →
   "SQL is not enabled for this Durable Object class" on every `hello`. Changed to
   `new_sqlite_classes`; **this cannot be corrected after the class is deployed**.
2. **DO SQLite `.one()` throws on an empty result set.** `readMeta()` and the cid dedupe
   lookup both used it, so a cold object (and the first-ever op with a cid) crashed
   immediately. Switched to `.toArray()`. The unit harness's fake storage returned
   `undefined` instead of throwing — it now mirrors the real throw, and reverting the fix
   fails 14 tests.

Also cleaned: the dev proxy never had a `/ws` entry (local dev could not reach the socket
at all), 20+ stale `/sync` comments, and the `AlbumRoom` comment in deploy.yml (the binding
is `Album`; a leftover `AlbumRoom` state dir confirmed the prototype origin).
Verification: lint / ts-check / test green (205 tests), plus a live `welcome` → `ops`
round trip through the Vite proxy.

## Lightbox gesture audit + fix

- Checked `web/src/lib/components/Lightbox.svelte` + `web/src/base/lib/lightboxEngine.ts` against the
  stated Ctrl/drag gesture spec (pin centre on Ctrl, rotate+scale on drag, snap on mouse-up, un-pin +
  hand to pan on Ctrl-up, smooth return to centre only when mouse AND Ctrl both released).
- Code already matches the spec's state machine; the one latent defect: `settleTransform` used a CSS
  `transition` for the return-to-centre, but the rotation-snap ease (`snapWithEase`) is a WAAPI
  animation on the same `transform`. A settle that began while the snap (160ms, motionMs('exit')) was
  still in flight had its transition shadowed by the snap, so the card hard-jumped to centre when the
  snap finished — violating "吸回的过程一定是平滑的，不能硬设置".
- Fix: `settleTransform` now animates with a single WAAPI keyframe from the _current rendered_ transform
  (`getComputedStyle().transform`) to the settled state, and cancels any in-flight `snapAnim` first. One
  animation owns `transform`, so the return is always continuous (continues a mid-snap rotation too).
- Verified: `npm run test -w infoto-web` (149 unit tests) green; `svelte-check` clean.
- NOTE: Playwright on Windows uses system Edge by default (`channel: 'msedge'` in playwright.config.ts),
  no browser download needed; e2e runs locally with `npx playwright test` (spins up Worker+Vite+media).

## Lightbox: plain drag on a zoomed/rotated photo now also springs back to centre

- User clarified: "已缩放/已旋转的图做普通拖拽也要回中心" — a plain single-pointer drag must recentre on
  release even when the media is zoomed/rotated. Previously a zoomed/rotated photo dragged freely and kept
  its offset (only the fit view recentred).
- Kept the deliberate-zoom paths (wheel zoom, double-click zoom, pinch) anchoring/keeping their offset;
  only plain drags and Ctrl gestures recentre. Implemented by giving `settleTransform`/`returnHome` a
  `keepPosition` flag: `false` (default) forces centre; `true` keeps via `engineSettlePan`. Call sites:
  wheel/dblclick (`zoomToPoint`) → keep; pinch end/tail/cancel + resting rule → keep; plain drag pan-end,
  Ctrl rotate/tail, Ctrl key-up → centre.
- Updated the 5 gesture e2e tests that locked the old free-pan behaviour to assert spring-back; also
  dropped a stale `transition` assertion in test #1 (settle now uses WAAPI + `transition:'none'`).
- Verified live against system Edge (Playwright `channel: 'msedge'`, already the Windows default in
  playwright.config.ts — no browser download needed): 6/6 gesture + 10/10 pinch e2e green. 149 unit
  tests + svelte-check clean.
