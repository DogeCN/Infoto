## DO/WS migration completed (afternoon, on `wip/do-websocket-migration`)

- **Design (ADR 0026):** the DO is stateless over D1. `worker/album-ops.ts` carries the write
  path (per-op `ts`, batched statement plan, snapshot) extracted from the deleted
  `routes/sync.ts`. `synced` answers with the same `SyncResponse`, so every client store is
  transport-blind. No DO storage, no `album_snapshots`, no compaction — the prototype's
  redundancies were all data-loss hazards.
- **Client:** `core/api/wsClient.ts` + a rewritten `core/engine.ts` (connection state on the
  store, offline IndexedDB queue with client-stamped `ts`, one-frame backlog flush, 16ms
  flush debounce, Turnstile over the hello, cookie mirrored from `welcome.uuid` so the next
  handshake re-issues it HttpOnly). `core/identity.ts` became `core/turnstile.ts`;
  `syncClient.ts` deleted. Sync button visibility: hidden when connected, shown when not.
- **Tests:** `album-ops.test.ts` (12) restores the write-path invariants the deleted
  `sync.test.ts` owned; `do/album.test.ts` (8) drives the protocol frame by frame;
  `syncEngine.test.ts` rewritten (11) for the WS engine; `admin.test.ts` recreated small for
  the surviving translate gate. Suite: 199 tests green (was 192 before, with the write path
  untested).
- **Scope call recorded in ADR 0026's amendment:** the prototype had deleted the admin
  mutation routes together with `/sync`; AGENTS.md §8.12 carves them out ("immediate
  user-initiated writes"), so they are restored verbatim and re-listed in `run_worker_first`.
- **Follow-ups:** e2e mocks still HTTP (routeWebSocket rework); admin mutation ops over WS
  if the HTTP carve-out is ever revoked; cross-client fan-out needs a per-connection op log
  in the DO plus client-side op appliers — deliberately deferred.
- Verification: `npm run lint` / `npm run ts-check` / `npm test` all green on the branch tip.
