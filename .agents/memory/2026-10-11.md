# 2026-10-11

## Five operator reports, five fixes

The operator reviewed the app against the previous session's answers and gave five directives. Each
was a behaviour change, so each lands with the code that describes it.

### 1. Open with cache, not an empty screen

**Problem.** `photos` starts `[]` and is only ever written by a `/sync` response; `metaCache` held
only `1`-valued per-sha dedupe entries. A returning visitor therefore saw the gallery's empty state
for the whole first round trip, and forever if the sync failed.

**Fix.** `metaCache` now also stores the whole last `/sync` response under the reserved key
`snapshot`. `rebuildCache` writes it (one function, so the clear cannot wipe it), `readSnapshot`
reads it, and `engine.init` delivers it through the new `onCachedSnapshot` IO before the first
request. `App.svelte` wires it to `store.applySync(r)` with no context, so no queued ops are
reapplied — the cached value is the raw server snapshot and the sync that follows folds the queue.
A read failure is swallowed; the sync still fills the store.

Deliberately **not** a versioned envelope: red line 1 says reset rather than add a compatibility
path, and the key can only ever hold a snapshot this code wrote.

### 2. Card mark badges are display-only

`PhotoCard`'s like/dislike/report badges were `<button>`s. They are now `<span role="img">` with a
plural accessible label (`{count} like(s)`, new `photoCard.likes/dislikes/reports` copy) and no
hover state. Every mark is made from the Lightbox, which keeps its own real buttons and the same
`onLike`/`onDislike`/`onRequestDelete` props — so `WaterfallLayout` still forwards them to the
Lightbox but no longer to the card.

### 3. The upload cancel control hides in multi-select

The uploading card's top-right cancel `<button>` (`z-30`) sat directly over the selection checkbox
(`z-10`, same corner) and swallowed the tap, so the corner cancelled the upload instead of selecting.
It is now rendered only when `!multiMode`. The failed-card dismiss is left alone: its opaque cover
already hides the checkbox, and failed cards are excluded from selection.

### 4. The progress sheet stopped following the finger

The operator's "不跟手" meant the touch drag of the upload panel, not the progress bar. A Playwright
probe (mobile emulation, real local upload, scripted drag) reproduced it exactly: the shell tracked
1:1 up to +149px, then **dropped to 120px and 64px while the finger kept moving up**.

Cause: the drag clamped to `naturalH()`, recomputed from the live row count every move, and
`panelRows` empties as jobs finish — so a completing row pulled the ceiling down under the finger.
The header constant was also 44px while the header renders 48px, jumping the sheet 5px on each drag
start.

Fix: freeze the ceiling at pointerdown, move the resting clamp into an effect skipped while
`dragging`, correct `HEADER_H` to 48, and move the gesture onto `base/lib/pointer.ts#startPointerResize`
(the second copy of hand-rolled `pointermove`/`up`/`cancel` MEMORY.md warns against). Re-measured
with a stable row set: finger +288px → shell +288px, monotonic.

### 5. The announcement editor takes any file; Markdown renders any media

`AnnouncementEditorDialog`'s input dropped `accept`; `uploadEditorImage` and the SW `addJob` skip
`routeByMime` for `purpose==='editor'`. The file is uploaded as-is, its extension surviving into the
URL. `markdown.ts`'s WebM-only `upgradeAnimatedMedia`/`isAnimatedArtifact` became
`upgradeMarkdownMedia`/`markdownMediaKind`, which maps a URL extension to `<img>` / `<video>` /
`<audio>`. `extFor` gained the audio/video MIME→extension entries those depend on.

The album's own `image/*,video/*` gate and both transcode legs are untouched.

## Second pass: the operator's three follow-ups

### 1. "If the frontend shows it, it is cached locally and readable offline"

Confirmed as the rule, and it exposed one real gap. The snapshot cache was wired into `App.svelte`
only — `Admin.svelte` still relied on `onSyncResponse` alone, so the admin tabs rendered nothing
until a server answered. Measured with `/sync` aborted in Playwright: before, gallery 4 cards but
admin announcements/polls/feedback all blank; after wiring `onCachedSnapshot` in `Admin.svelte` too,
all three present. `selfId` is already in localStorage, so the root-only feedback gate survives the
reload as well.

Two honest limits, both outside this rule: the **media bytes** still come from the image host (the
album caches metadata, not artifacts), and an **upload** cannot complete offline by construction —
its card and its ops stay queued in IndexedDB and OPFS until a sync lands.

### 3. Failed cards are selectable now, and the cover is semi-transparent

`WaterfallLayout` excluded failed uploads from selection as well as preview, which stranded the one
card that most needs the batch delete. Removed from `toggleSelect`, `handleLongPress`, `selectAll`
and the marquee; the Lightbox exclusion stays (there is nothing to look at). The failure cover went
`bg-black/75` → `bg-black/55`, matching the uploading curtain: a failed card is still a card in the
grid, not a hole in it.

Making failed cards selectable immediately re-opened the corner collision, so the hiding rule covers
**both** dismiss controls: the uploading cancel and the failed card's dismiss. The failed card's
retry is left visible — it is centred, not in the corner. Verified with a real failed upload on a
mobile viewport: multi-select off → 1 Remove button; on → 0 Remove buttons, retry still present, and
tapping the corner sets `aria-pressed` instead of dismissing the card.

### 5. "File", and non-media files land as links

The toolbar button is **File** (`copy.editor.tools.file`, `FileUp` icon). Inserting a hosted file
now goes through `insertMediaAt`, which shares one predicate with the renderer: `isEmbeddableArtifact`
is true for an image, video or audio extension and **false** for anything else, so a `.pdf` /
`.zip` / extension-less URL becomes `[name](url)` instead of `![alt](url)`.

Two wrong turns worth the lines. Writing it as `markdownMediaKind(url) === 'image'` looked right and
was not — `'image'` is that function's fallback for anything unrecognised, so it would have linked
every image and embedded every PDF; the test caught it (an mp4 came out as `[clip](…)`). Then
`isImageArtifact` (image extensions only) was the obvious second guess and was wrong in the other
direction: an mp4 is renderable, so it must embed.

The renderer closes the loop: `upgradeMarkdownMedia` now also converts `![alt](url.pdf)` into
`<a class="markdown-file" download>`, so hand-written or legacy Markdown gets a link rather than a
broken image. Verified in the browser: mp4 → `<video>`, mp3 → `<audio>`, png → `<img>`, pdf/bin →
`<a href download>`.
