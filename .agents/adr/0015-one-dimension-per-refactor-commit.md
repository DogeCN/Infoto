# 0015: One Dimension Per Refactor Commit, and a New Abstraction Is Specified Before It Is Used

- **Date**: 2026-10-03
- **Status**: Accepted
- **Context**: A retrospective over the whole commit history asked one question: which commits were refactors, and was each a net win. The answer was uncomfortable. Of every commit titled `refactor` / `restructure` / `normalize` / `chore`, only a handful changed structure without changing behaviour, and the damage correlated perfectly with one variable — how many unrelated dimensions a single commit carried.

  The worst case, `189b47a` "Normalize the codebase: one owner per concern" (96 files, +3456), carried five at once: design-token unification, component merges (`AdminCollection`, `EditorDialog`, `pillMeasure`), a test-stack migration (24 files from `describe/it/expect` to `test` + `node:assert`), a semantic change (admin writes read the store's locale), and a visual change (the Lightbox's six per-action menu colours flattened to grey). It shipped three production bugs, each of which needed its own follow-up commit:

  - `66d91b7` — the new `base/lib/motion.ts` declared `motionMs(name: 'duration-enter' | …)` and then built `` `--duration-${name}` `` internally, so every caller produced `--duration-duration-enter`. The fallback lookup missed, the duration became `NaN`, and the page went blank. Every component importing that module failed to start.
  - `f8b6209` — the new `base/lib/hover.ts` exposed state through a plain closure (`hovered: () => boolean`). Svelte cannot see a read that happens inside a function call, so the consumers' effects ran once at mount and the hover state froze at `false` forever.
  - `4a6b7d0` — the "eliminate the double source" half only converted the _writer_. Admin writes began reading `store.contentLocale` while the read path kept `activeLocale()`, upgrading a cosmetic optimistic-row mismatch into rows that were written and then never displayed.

  The second-worst, `d54aa95` "Refactor shared lifecycle and enforce explicit sync triggers" (120 files), paired a genuine structural win (`base/lib/overlay.ts`, `state/uploadStore.svelte.ts`, both still the sole owner today) with a product-level behaviour change (deleting the oplog sync threshold and the entire retry mechanism). It also added the overlay action with an `enabled` option and wired `use:overlay` into the Lightbox without passing it; `OverlaySidebar` and `ActionSheet` both honoured the contract, so the bug hid for three days until `b5eb3b4`.

  Two structural findings make this worth a permanent record rather than a habit note. First, the failures that cost the most were not bad code but **bad commit boundaries**: with five dimensions in one commit there is no revert granularity and no bisect granularity, so a `git revert` of the token work would also roll back the component merges and the test migration. Second, every one of the three bugs above was a **new abstraction shipped and immediately spread across five call sites in the same commit**, with no test pinning its contract — and lint, `tsc`, and the unit suite were all green throughout, because `motionMs('duration-enter')` and a closure-returned boolean are both perfectly type-legal. The green static check was a false signal.

- **Decision**:
  - **One dimension per refactor commit.** A refactor commit carries exactly one of: pure path move, module merge, component extraction, token unification, test-stack migration, or semantic change. It may not carry a visual, layout, spacing, motion, or copy change.
  - **The one permitted exception is value-preserving.** Replacing a literal with the token whose value equals it (`#f43f5e` → `text-destructive`) is part of token unification, not a visual change. `ca1b082` shows the line: it hardcoded `0.45s cubic-bezier(…)` into `.card-motion` one commit after `189b47a` built `motion.ts` to make the tokens the single source — a bypass, not an exception.
  - **A newly extracted abstraction ships with its contract test, before its first use.** If the contract cannot be written down as a test, the abstraction is not ready to be extracted. `66d91b7`'s `motion.test.ts` is the worked example: it asserts per phase and deliberately feeds `'0.5s'`, `'  '`, and `'var(--nope)'` to force the fallback branch. That abstraction has not been touched since.
  - **A module merge deletes the old files in the same commit.** `d915d61` merged `oplog/cache.ts` and `oplog/store.ts` into `oplog.ts` but left the two dead files on the tree until `fd5984a`; `7e5a633` left `src/d1-shim.ts` and `src/testSupport.ts` for the same reason. Orphan modules survive a "merge" because nothing references them, and nothing references them because the merge already replaced them.
  - **"Eliminate a double source" changes every reader and every writer of that value, or none.** Half a convergence turns a small inconsistency into a large one.
- **Consequences**: Every refactor becomes independently revertible and independently bisectable, and `git log -- <path>` stays a usable explanation. The cost is more commits and a little more ceremony, and it means a genuinely large mechanical move (`31ffb82` rewired 84 files) has to be argued for as pure: it earns that by being provably a pure move, which `git diff --stat` per file can demonstrate (`transcode/protocol.ts` at +2/−4). The rule also gives a cheap self-check: if a refactor commit's message cannot name its single dimension, it is not a refactor commit, and the message is telling the truth about what happened. In practice this is the discipline that would have kept `189b47a`'s three regressions from reaching main — each was separable, so each would have been reviewable on its own, and the motion signature would have been caught by the test it should have shipped with.
- **Alternatives considered**:
  - _Rely on review discipline alone_: rejected — the three `189b47a` bugs each passed a review that was checking the dimension the reviewer expected to find. `3367991` ("translate comments to English") carried a complete 313-line `ErrorPage` rewrite and a deleted `message` prop; `ac96442` ("Chore") changed the Lightbox's neighbour-probe algorithm and its own message described a toast close button that had not existed for a commit.
  - _Ban large refactors outright_: rejected — `e8c2340` (32 renames) and `31ffb82` (84 files) were both net wins precisely because they were large _and_ pure. Size is not the variable; mixed dimensions are.
  - _Allow visual changes but require them last in the commit_: rejected — commit order does not survive `revert`, and a squash merge destroys it entirely. `189b47a`'s colour flattening and `6217c37`'s `letter-spacing` / `color-scheme` edits each made their revert a gamble on whether the design came back too.
  - _Require the contract test in a follow-up commit_: rejected — `189b47a` shows what "follow-up" means in practice: by the time the test is written the abstraction is already spread over five call sites, so the test encodes whatever they happen to do instead of what they should do.
