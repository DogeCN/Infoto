# 2026-10-05 — Domain migration off cc.cd

## Why

The `cc.cd` free-suffix is SNI-keyword-blocked by the GFW (connection reset during TLS
handshake, IP-agnostic — verified by cross-matrix probes: any `*.cc.cd` SNI resets on any
IP, other SNIs on the same IPs pass; DNS is clean, not polluted). Both `infoto.cc.cd` and
`upload.infoto.cc.cd` (the media facade) became unreachable for direct mainland visitors.
ECH (Cloudflare default, works over DoH) hides the SNI and bypasses the block — verified
end-to-end with headless Firefox (DoH + ECH loaded the site with 200), but that is a
per-visitor mitigation, not a fix.

## New layout

- Album prod: `infoto.dpdns.org` (DigitalPlat free domain, on the Public Suffix List, so
  it is its own Cloudflare zone — same mechanism `infoto.cc.cd` used).
- Album dev: `dev.infoto.dpdns.org`, media facade: `upload.infoto.dpdns.org`.
- Old `infoto.cc.cd` / `dev.infoto.cc.cd` / `upload.infoto.cc.cd` stay bound to the same
  Cloudflare zones but now serve 301 redirects (Bulk Redirects, subpath matching + path
  suffix + query string preserved) to the dpdns equivalents. Cookies cannot be shared
  across the two registrable domains; the 301 keeps identity on the single new domain.
- Repo variable `MEDIA_HOST_URL` updated to `https://upload.infoto.dpdns.org` (the facade
  serves the same JSON error envelope there; Turnstile widget `0x4AAAAA...eFm1` already
  lists the new hostnames, so `TURNSTILE_SITE_KEY` was unchanged).

## Gotchas

- dpdns.org resolution intermittently fails on some mainland ISP resolvers (the same ISP
  hijack box that serves "Cdn Cache Server V2.0" pages); the site itself answers fine via
  DoH or pinned IPs. Tell affected visitors to use 223.5.5.5 or browser DoH.
- `*.cc.cd` cannot be observed with plain curl from a mainland vantage point — the GFW
  resets the TLS handshake before Cloudflare's edge answers. Verify old-domain behaviour
  (redirects included) with an ECH-capable browser (Firefox + DoH) or via Host-header
  probes from outside the filter.
- Free-suffix choice ruled by three checks: PSL membership (CF zone admission), fake-SNI
  probe (not keyword-blocked), consistent resolution across CN/foreign resolvers. `qd.je`
  failed the PSL check; `cc.cd` failed the SNI probe. `.dpdns.org` passed all three.
