# 2026-10-03

## All-locale sync replaces the locale-selected snapshot (ADR 0013)

`/sync` now returns every locale's announcements, polls, and feedback, and the client derives the visible lists from `contentLocale`. A language switch is a local re-render — no request, no clearing. The client keeps one all-locale bucket per content type and writes are addressed by an explicit locale, so a response that lands after a switch still commits into the language it was made for. This removes the class of bug where the engine read `activeLocale()` while admin writes were filed under `store.contentLocale`.

Removed with it: `SyncRequest.locale`, `SyncResponse.locale`, `EngineIo.locale`, `keepalivePrefix`'s locale parameter, and the engine's locale-keyed coalescing. `AdminCollection` takes `rows(locale)` / `setRows(locale, rows)` instead of a single-locale pair plus an `isCurrentLocale` guard.

## Poll references are `::poll:<lang>:<id>`, and polls have no title

A reference resolves only when the language **and** the id both match a known poll; anything else — unknown language, malformed, or the legacy `::vote:<id>` — stays plain Markdown. Polls stay locale-scoped records. The poll title was removed from the record, the editor, the schema, and the migrate export; the admin list identifies a row by choice mode and timestamp.

Consequence to remember: without a title, "title-only edits keep votes" is gone. Any change to the option set or the choice mode clears the poll's votes.

## Design reverts: the normalization pass flattened three things that were better before

- **`GlitchText` hover burst.** The ambient-only retime (`--glitch-burst`) never exceeded ~6px of displacement. The dedicated `burst-a`/`burst-b` ramps (~18px, `skewX`, clip slices) are back, keeping the newer class names and the cyan ramp.
- **`Lightbox` action sheet.** The per-action colours are the scanning cue; the neutral-everything pass removed it. `sky` / `violet` / `teal` / `amber` / `success` are restored per row, `destructive` stays unique.
- **Frontend design-rationale comments.** `8e4b62d` restored the backend comments only, so the frontend rationale for `TOP_GAP`, the bar probes, and the sliders stayed lost. Restored where the code still lives; where the code moved (`pillMeasure.ts`, `topbarFit.ts`) the comment went with it.

## Behaviour changes

- **A failed upload never auto-retries.** `failJob` deletes the persisted resume record, so a later page load cannot re-run `/upload`. Interrupted-mid-transfer resumes are untouched, and the artifact stays in OPFS for a same-session manual retry.
- **Layout preview is fully transparent.** While a layout slider is dragged, the panel background is cleared and every region except the dragged slider's own row goes to `opacity-0` (never an ancestor opacity — that would take the live slider thumb with it).
- **The dragged slider's row cannot flicker.** `active` was `value !== defaultValue`, so crossing the default mid-drag (the band slider's 260px) dropped the row's highlight for a frame. It is now `value !== defaultValue || drag`; the resting rule is unchanged.

## Dev-phase rule restated by the user

Pure development: no fallbacks, no migrations — a schema change resets the local database (`npm run db:reset`). The `TimeLabel` poll-date render guard (added when `polls.updated_at` landed) was removed under this rule; every row has the column now.

## Admin editor drafts survive tab switches (page memory)

Switching the admin pill row used to close an open editor and throw the draft away. The dialogs now export `getDraft()`; `handleTabChange` captures the live draft, closes the editor, and re-seeds the fields via a `draft` prop when the user returns. Page memory only — a reload clears it. A locale change still discards drafts (existing intent).

## Poll-list timestamp moved to its own row

The announcement list keeps the edc455b look exactly (`shrink-0 tabular-nums`, inheriting the parent's `text-xs`).

## Turnstile test-secret mismatch broke identity creation on the test deployment

`deploy.yml` injected `0x0000…00` as the non-production `TURNSTILE_SECRET_KEY` — a value invented to "look like" a dummy key, but it is on no Cloudflare doc. `siteverify` rejected every token, so `verifyTurnstile` failed, no user row was ever created, no cookie was set, and every sync re-challenged (`turnstile_failed` in the console). CI never caught it because nothing exercises the deployed secret. Same class of mistake as the never-tested USTCLUG font mirror. Fixed to the published `1x0000…AA` (which `turnstile.ts` short-circuits on), with cross-reference comments in both files. Recorded in MEMORY.md under Verification Discipline and Identity & Turnstile.

Two deployment facts learned the hard way the same day:

- **Deleting a Worker also drops its custom-domain binding.** `wrangler deploy` recreated the Worker but `dev.infoto.cc.cd` returned `error code: 1016` until the domain was re-attached in the dashboard. `wrangler.toml` has no `routes`; adding per-target routes is the open option if this recurs.
- **The zone's bot protection challenges datacenter IPs** (403 "Just a moment" on GET/POST from the proxy), so curl cannot end-to-end verify `/sync` on the deployed site — browser traffic is unaffected.

## Refactor retrospective → ADR 0015

Question asked: which commits were refactors, and was each a net win. Method: four parallel passes over
the history, each reading the actual diffs for a date cluster rather than the commit titles, then
cross-referencing every candidate's touched files with `git log --follow` to find the follow-up commits
that came to repair it.

The variable that predicted damage was **not size** — it was how many dimensions one commit carried.

**Net wins:** `97819d8` (TooltipIconButton, zero behaviour change, the model), `f4869b0`, `31ffb84`'s
`31ffb82` (84 files but provably pure moves), `e8c2340` (32 renames), `3ac82c2`, the three-commit image-host
decoupling (`c59adb0` → `874167b` → `c481e04`, no compatibility layer anywhere), `a368e59`, `7e5a633`,
`f86a5a6`, `17e587d`.

**Net losses:** `189b47a` (96 files, five dimensions, three production bugs, zero revert granularity),
`fd5984a` (title said "consolidate unit tests"; actually a 317-line `TopBar` rewrite plus a
`layout.cols`→`layout.band` inversion that voided user settings twice), `2cfb4ef` (locale as a
module-load constant), `3367991` (313-line rewrite inside a "translate comments" commit), `ec40dbd`
(suite cut 208→49 by case count), `b43b139` (guessed `TOP_GAP=16`, reverted 1.5 h later), `fb755d5`
(14 shadcn files, 339 lines, never imported once).

Three findings worth keeping beyond the ADR itself:

- **All three `189b47a` regressions passed lint, `tsc` and the unit suite green.** `motionMs('duration-enter')`
  and a closure-returned boolean are both type-legal. Static checks verify types and syntax, never a
  contract that was never written down.
- **The cheap judgement test needs no review**: `git log --follow` a moved file and look for follow-ups
  titled Fix / Revert / Restore. Zero is the good signature. That is what separated the two groups here.
- **Squash merges strip functional comments, and one stripped comment was factually wrong.** `8e4b62d`
  had to restore six files after `6217c37`; the `schema.sql` users.id note contradicted `f86a5a6`'s
  in-INSERT id computation, so following it would have broken `ROOT_ID`. ADR and memory files are code.

Also settled: `6217c37` and `189b47a` are **not** two copies of one refactor —
`git merge-base --is-ancestor` makes the former the ancestor of the latter, and they differ (the first is
pure structure, the second changes behaviour on top of it). Earlier they looked like a duplicate pair.

Recorded in `.ai/adr/0015-one-dimension-per-refactor-commit.md` and MEMORY.md §Refactor Commit
Discipline. The visual and behavioural half of this retrospective (the icon-colour saga, the pill
measurement, the three waterfall rewrites, the `/l/` probe churn, the invented Turnstile value) was
already covered by `.ai/CONTRACT.md` §4 and was not duplicated.

## Two error-page surfaces, and they were never the same page

Chasing the `3367991` finding that `ErrorPage.svelte` lost its `message` prop turned out to be a
non-issue, and checking why produced the real fact: **the SPA judges 404 only, and 5xx has always
been the Worker's page to draw.** `ErrorPage.svelte` takes just `code`, and both call sites
(`Root.svelte:24`, `Admin.svelte:329`) pass `code={404}`, so `pageHeading` / `notFoundMessage` being
constant is correct behaviour rather than a bug — do not add a message prop back. `src/worker/errors.ts`
serves `notFoundPage` (arbitrary paths, `/admin/*`, missing or deleted `/l/:id36`) and `serverErrorPage`
(`onError`), each with its own wording and `Accept-Language` output. `ca1b082`'s catch-all tightening is
why these pages are nearly invisible: before it, any path returned `index.html`.

The two 404 wordings differ on purpose — the SPA's is a route miss, the Worker's also covers a removed
image — but the keys read as a coincidence, so `errorPage.notFoundMessage` → `spaNotFoundMessage` and
`errorPage.pageHeading` → `spaPageHeading`. Comment on the table records why. CONTRACT.md §3's Error
page entry is no longer a `TODO(contract)`; it now states the split and that the SPA has no 5xx branch.

## Lightbox gesture rewrite, against the v1 reference

> Merged from `.workbuddy/memory/2026-10-03.md` — a WorkBuddy-local log kept in a gitignored
> directory, so it was invisible to every other agent. `.ai/memory/` is the canonical location.

Measured against `D:\ToDo\v1\public\lightbox.js` (four-way gestures + two-finger pinch) and fixed in
`web/src/lib/components/Lightbox.svelte`, with rotation added:

- Pinch now scales **about the two-finger midpoint** (recomputed every frame from the pinch start's
  `s`/`x`/`y`, so there is no cumulative drift); it previously only changed `scale` and always pivoted
  on the centre (defect 1).
- `clampPan` moved to the real wrap/stage rect residual instead of the stage dimensions, so zooming
  back out no longer reveals black edges (defect 2).
- The pan gate moved from `scale > 1.01` to `isZoomedBeyondViewport()` (only pan when the rendered
  box truly exceeds the viewport), fixing images that were zoomed but still smaller than the
  viewport being wrongly pulled into pan mode (defect 3).
- A pinch end is guarded by `pinchActive` and settles on the first finger lift, snapping rotation to
  90° instead of falling through to a four-way swipe (defect 4).
- Touch double-tap zoom became an explicit `_lastTap` detector (native `dblclick` is unreliable under
  touch + `touch-action:none`); the mouse keeps `onDblClick` (defect 5).
- Two-finger rotation was added, snapped to 90° on release (defect 6, per the Refactor.md spec).

The two features the user asked for turned out to already exist and were confirmed preserved: tapping
the left/right half of the black mask pages (`handleStageClick`), and Ctrl+drag emulating a pinch
(the `ctrlZoomPointer` branch).

Behaviour changes were recorded in the Lightbox section of `.ai/CONTRACT.md` (red line #8).
lint + ts-check + 72 unit tests green.
