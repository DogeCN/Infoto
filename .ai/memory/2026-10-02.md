## Second pass — the open questions, closed

The user settled the four items left standing, with one exception: **editor images are not deduplicated.**

1. **`putSha` deleted.** It had no production caller, and the `'editor'` purpose it wrote was therefore unreachable. The sha cache is now exactly what it is used for: `isKnownAlbumSha(db, sha)` returning a boolean, backed by the snapshot's hashes and replaced wholesale each sync. `ShaEntry`, `cacheKey`, and the cursor walk that preserved editor entries across a rebuild all went with it — the "keeping editor entries" behaviour was protecting rows nothing could write. `rebuildCache` is now a `clear()` plus one `put` per photo.
2. **The admin editor dialogs are modal.** The "Non-modal editor panel" comment was _why_ they had escaped `overlay.ts`; with that settled, both run through a new `EditorDialog.svelte` that owns the shell, scroll region, footer, focus trap, scroll lock and Escape. Each dialog passes only its body. `onMount(() => titleInput?.focus())` is gone — the overlay focuses the first focusable element, which also gives the poll dialog a focus target it never had.
3. **Admin writes take their locale as an argument.** `adminClient` read `activeLocale()` for the body while the store filed the optimistic row under `contentLocale`. Every create/update/reorder now takes `LocaleCode` explicitly, and the store passes `this.contentLocale`.
4. **One pill measurement.** `SegmentedControl` summed `invisible` label-copy widths; `SortPill` used a clone probe. The sum was the "hidden copies lie" trap MEMORY warns about, so the clone probe won and moved to `pillMeasure.ts`. Both the admin tabs and the gallery sort pill now report comparable widths through the same action — previously the admin path never even forwarded `onWidths`.
5. **One test convention.** 20 files across both suites converted from `describe`/`it`/`expect` to `test` + `node:assert/strict`, flattening each `describe`/`it` pair into `test('Group: Case')`. Test counts are unchanged (59 + 57). Four subagents did the bulk in parallel, each verifying its own files.

Converting surfaced one real semantic difference worth keeping: `expect(...).toEqual` ignores `undefined`-valued keys, `assert.deepEqual` does not. `uploadClient.test.ts` had been passing only because of the looser check — the result carries `detail: undefined`, now asserted explicitly.

## Left standing

- **`putPendingUpload`/`clearOps` are test-only helpers living in production modules.**
- **`SegmentedControl` and `SortPill` now share one measurement, but `SortPill` is a thin wrapper** over `SortTabs` + `pillMeasure`. If a third segmented pill ever appears it can skip both.
- e2e still needs the real local stack; the rewritten pagehide test in `pipeline.spec.ts` has not been executed locally.

## Fix: the two P1s landed (all gates green)

Seven existing files plus one new module, and ADR 0012.

### P1-a media host config degradation (red line 1)

- `isAllowedMediaUrl()`: predicate changed from `(env.mediaHostUrl ?? LOCAL) !== LOCAL` to
  `env.mediaHostUrl !== undefined`. Semantics: the local exception applies **only when the variable
  is absent entirely**; pointing `MEDIA_HOST_URL` at loopback explicitly is now judged by the strict
  production rule (it used to be mistaken for "local" and waved through). A missing config is a
  production misconfiguration, not a reason to relax.
- `.github/workflows/deploy.yml` now hard-fails: the comment claimed it "hard-fails below" but the
  "Inject Worker secrets" step below it had been removed in a diff, leaving only an `if [ -n ]`
  silent skip. Empty `MEDIA_HOST_URL` now `exit 1`s.
- Test: `media.test.ts` gained an "explicit loopback is refused too" case pinning the new contract.
- ADR 0009 corrected: its Consequences claimed it "fails the deploy loudly", which was false at the
  time.

### P1-b ADR 0003 landed only in TopBar

Root cause: `--bar-h` was published only on `<header>`, and CSS variables do not inherit across
sibling subtrees, so external consumers had no choice but to guess. The two `EditorDialog`s'
`top-14 md:top-16` (56/64px) were exactly re-typing the bar's height breakpoints as media queries,
and `WaterfallLayout` was recomputing the ramp with `barHeight(containerW)` — the canvas width, not
the bar width.

- Added `web/src/state/barHeight.svelte.ts`: `barHeightPx` + `barHVar(fallback)`.
- `TopBar.svelte` writes **both** `--bar-h` on `document.documentElement` and `barHeightPx` in one
  `$effect`, cleaning up both on unmount.
- `WaterfallLayout` now uses `barHVar()`; `barHeight(containerW)` stays only as the pre-measurement
  fallback.
- Both `EditorDialog`s → `top-[var(--bar-h,3.5rem)]`, breakpoints deleted.
- Added **ADR 0012** ("publish the measurement once, consume it everywhere") and registered it in
  `.ai/adr/README.md`.
